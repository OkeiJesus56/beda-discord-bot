# Discord-бот BEDA

Бот для заявок в клан, личных дел участников, событий, временных голосовых комнат и карточки сервера WARDOGS «Где играем».

Зелёная кнопка «Подать заявку» открывает анкету: Steam ID, имя, возраст, город и удобный период для вступительного разговора по МСК. Все пять полей обязательные. После отправки бот создаёт канал для заявителя и офицеров. Администраторы сервера тоже имеют доступ, как предусмотрено Discord. Кнопка «Закрыть заявку» — красная.

На каждую новую заявку создаются текстовый и голосовой каналы в выбранной категории. Голосовой канал доступен заявителю, рекрутерам и администраторам; ссылка на него указана в анкете. Боту нужны права управления каналами и разрешениями, а также право Connect («Подключаться»), чтобы разрешать подключение участникам. Сам бот в голосовой канал не входит.

Одна открытая заявка на человека. Офицер закрывает заявку кнопкой: голосовой канал удаляется (в том числе если собеседование ещё идёт), переписка сохраняется, текстовый канал скрывается от заявителя. Доступ рекрутеров и администраторов сохраняется. Если сам заявитель — администратор или владелец сервера, Discord позволяет ему видеть канал независимо от запрета. Заявитель может подать новую заявку. Закрытые текстовые каналы можно удалить вручную. Бот не выдаёт роль участника автоматически. Кнопки и состояние заявок сохраняются после перезапуска. Существующая база обновляется автоматически; для старых тикетов голосовые каналы задним числом не создаются.

## 1. Создать приложение и пригласить бота

1. Откройте https://discord.com/developers/applications → **New Application**, имя `BEDA`.
2. На странице **Bot** получите токен через **Reset Token**. Сохраните его только в локальном `.env`, не отправляйте в чат.
3. На странице **Installation** включите **Guild Install**. В настройках установки выберите scopes `bot` и `applications.commands`.
4. Права бота: **View Channels**, **Send Messages**, **Embed Links**, **Attach Files**, **Read Message History**, **Manage Channels**, **Manage Roles**, **Connect**. Manage Roles нужно для изменения прав заявителя. Administrator боту не требуется. На странице **Bot → Privileged Gateway Intents** включите **Message Content Intent**: он нужен для сохранения сообщений участников и вложений в транскрипт.
5. Откройте предоставленную Discord ссылку установки и выберите свой сервер. У вас должны быть права управления сервером.
6. В Discord включите **Настройки пользователя → Расширенные → Режим разработчика**. Правой кнопкой по серверу → **Копировать ID сервера**.

## 2. Настроить и запустить на Windows

Нужен Python 3.11 или новее. В PowerShell в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Заполните файл:

```dotenv
DISCORD_TOKEN=токен_со_страницы_Bot
DISCORD_GUILD_ID=id_вашего_сервера
```

Запустите:

```powershell
.\.venv\Scripts\python.exe bot.py
```

Если `.env` уже существует, не копируйте поверх него пример. Пока процесс работает и компьютер подключён к интернету, бот онлайн. Для круглосуточной работы позже можно перенести его на сервер. Запускайте только один экземпляр с этой базой.

## 3. Опубликовать кнопку

1. Создайте роль офицеров и назначьте её тем, кто рассматривает заявки.
2. Создайте категорию для тикетов и канал, например `заявки-в-beda`.
3. Убедитесь, что права бота не запрещены настройками категории и канала.
4. От администратора выполните в канале `/setup_tickets`, выбрав категорию и роль офицеров. Бот опубликует кнопку.
5. Проверьте с обычного участника: отправьте анкету, убедитесь, что другой участник не видит тикет, повторная заявка ведёт в существующий канал, офицер видит заявку и может её закрыть.

Если команда не видна, проверьте ID сервера, установку с `applications.commands`, перезапустите Discord и посмотрите консоль бота.

## Настройки и данные

### Личные дела участников

1. Установите зависимости из `requirements.txt` и перезапустите бота.
2. Создайте форум личных дел без обязательных тегов и семь отдельных ролей: BEDA и шесть специализаций. Роль бота должна быть выше выдаваемых ролей, с правом «Управлять ролями». В форуме разрешите боту просмотр, создание публикаций, отправку сообщений в ветках и вложений. Настройте доступ участников к форуму.
3. Администратор выполняет `/setup_dossiers`: `forum` — форум, `beda` — BEDA, `assault` — Штурмовик, `medic` — Медик, `mechanic` — Механик, `builder` — Строитель, `pilot` — Пилот, `sniper` — Снайпер.
4. В новом тикете администратор нажимает «Успешное собеседование». В старом тикете, где кнопки ещё нет, используйте `/approve_interview`.
5. Заявитель нажимает «Заполнить личное дело», вводит ник и имя, выбирает две разные специализации и нажимает «Отправить анкету». Steam ID и город переносятся из исходной заявки тикета. В новой заявке поле «Город» заменяет прежний часовой пояс. Выбор специализаций действует 15 минут.
6. Администратор вызывает `/review_dossier` в том же открытом тикете. Бот показывает анкету и кнопку «Создать личное дело» в личном ответе, который заявитель не видит. Только после нажатия администратором бот создаёт тему и выдаёт заявителю BEDA и обе роли специализаций. Повторная отправка анкеты делает старую кнопку проверки недействительной: нужно снова вызвать `/review_dossier`. Закрытие тикета остаётся отдельным действием.
7. Для старых тикетов бот восстанавливает Steam ID и город из исходного сообщения бота. Если в старой заявке был только часовой пояс, город остаётся пустым: администратор указывает его через `/review_dossier city:Екатеринбург`. Аналогично доступен параметр `steam_id`. Часовой пояс больше не запрашивается и не проверяется.

Discord не позволяет администратору открыть модальное окно у другого пользователя: поэтому заявитель открывает анкету своей кнопкой. Кнопка и одобрение сохраняются после перезапуска; незавершённый выбор специализаций нужно открыть заново.

Карточка — стандартный Discord embed: ник, имя, Steam ID, город и обе специализации отображаются обычным текстом. Исходная PNG основной специализации прикрепляется без изменений и показывается под текстом внутри карточки. Текст на изображении не рисуется; Pillow и шрифты больше не требуются. Файлы лежат в `assets/specializations/` и сопоставлены по русским именам. Исходные файлы из Downloads больше не нужны для работы бота. Данные анкеты, черновик проверки и ID темы сохраняются в SQLite. Уже опубликованные карточки автоматически не меняются; редактирование пока не реализовано.

Повторное создание возвращает существующую тему. Если тема создана, но выдача ролей прервалась, администратор снова открывает `/review_dossier` и нажимает кнопку создания: бот завершает выдачу ролей по сохранённым данным. При тайм-ауте публикации запись остаётся в `publishing`: автоматический повтор отключён, поскольку Discord мог уже создать тему. Остановите бота, сделайте резервную копию базы и проверьте форум: если тема есть, укажите её ID в `dossiers.thread` и статус `roles_pending`; если темы точно нет, удалите только соответствующую запись `dossiers` по `guild` и `owner`. После запуска администратор может повторить создание. Используйте только один экземпляр бота с этой базой.

Локальная проверка: `.venv/Scripts/python.exe -m unittest discover -v`. Тесты используют временную базу в памяти и не подключаются к Discord. Проверка оформления выполняется без вывода изображений; окончательный вид следует проверить в Discord после запуска.

### Временные голосовые комнаты

Создайте постоянный голосовой канал `➕ Создать комнату` и категорию для комнат. Выполните от администратора `/setup_voice_rooms hub:... category:...`. При входе человека бот создаёт `🔊 Ник` и переносит его туда. Другие участники заходят обычным способом. Права наследуются от категории; создателю не выдаются администраторские права. При возвращении в канал создания бот использует сохранившуюся комнату этого участника.

Боту нужны «Просматривать каналы», «Подключаться», «Перемещать участников» и «Управлять каналами»; участникам — просмотр, подключение и возможность говорить в категории. Voice States включён в коде, дополнительных привилегированных intents для этой функции не нужно. Бот не подключается к голосу, голосовые библиотеки не требуются.

Пустые созданные комнаты удаляются при выходе последнего участника. Для только что созданных комнат есть защитная задержка 20 секунд; фоновая проверка раз в 30 секунд убирает оставшиеся пустые комнаты и после перезапуска. Состояние хранится в SQLite. Постоянный канал создания, обычные голосовые каналы и комнаты собеседований этой функцией не удаляются. Пока бот выключен, создание и удаление не работают.

### Карточка «Где играем»

В активной карточке есть кнопка **«Я коллер»** для роли `caller_role`, выбранной в `/setup_where_play`, и администраторов. Сначала зайдите в голосовой канал, затем нажмите кнопку и выберите деятельность: **Штурм, Стройка, ДРГ или Разведка**. Бот создаст комнату `Штурм - Ник` (с выбранной деятельностью) в категории из `/setup_voice_rooms` и перенесёт вас туда. Уже существующая временная комната участника используется повторно и переименовывается под выбранную деятельность. Меню видно только нажавшему и действует 3 минуты; после истечения срока нажмите «Я коллер» снова. Лимит — 5 комнат коллеров. Перед созданием повторно проверяются права, активность карточки и нахождение в голосовом канале. В разделе «Коллеры» появляются упоминания участников и ссылки на голосовые комнаты. Список обновляется в течение 15 секунд и показывает только тех коллеров, кто находится в своей комнате. Когда комната пустеет, она удаляется механизмом временных комнат. Кнопка и связи сохраняются после перезапуска. `/stop_play` отключает кнопку и убирает список с карточки, но не удаляет занятые комнаты.

1. Создайте текстовый канал `🎮・где-играем`, доступный участникам. Боту разрешите просмотр канала, отправку сообщений и встраивание ссылок.
2. Администратор выполняет `/setup_where_play channel:#где-играем caller_role:@Коллер`. Роль необязательна; без неё управляют только администраторы. Настройки сохраняются в SQLite.
3. Коллер или администратор из любого канала сервера (в том числе скрытого) вызывает `/where_play server:001234 team:🔵 Синие`. Укажите код подключения из игры, а не название и не ID запущенного экземпляра. Для community-сервера код может быть UUID. Цвет вводится вручную.
4. Бот обновляет одну карточку с сервером, кодом, регионом, картой, заполненностью и коллером. Время Discord отображает в часовом поясе читателя. Участникам достаточно скопировать код из карточки.
5. `/stop_play` завершает сбор и останавливает опрос для этой карточки. Для нового сбора снова используйте `/where_play`. Повторная `/setup_where_play` позволяет сменить роль и перенести карточку в другой канал, удалив прежнее сообщение.

API: https://wardogservers.com/devs. Опрос не чаще `meta.refreshSeconds` и не чаще раза в минуту, с ETag. Ключ не нужен. После перезапуска активные карточки обновляются снова. Устаревшие данные и сетевые сбои помечаются предупреждением; если сервер пропал из списка, последний выбор сохраняется. Автоматического переключения серверов и определения цвета команды нет. Если сообщение удалено вручную, при следующем обновлении бот создаст новое. Если удалён сам канал, настройте другой через `/setup_where_play`.

После закрытия заявки появляется кнопка **«В архив»** для рекрутеров и администраторов. При первом архивировании бот создаёт закрытый канал **#транскрипты** (доступ рекрутерам и администраторам). Он отправляет ZIP с `transcript.html` и копиями вложений, затем удаляет канал заявки. Для просмотра скачайте ZIP, распакуйте и откройте HTML. Архив содержит сохранившиеся сообщения на момент выгрузки, даты в UTC, авторов, анкеты и вложения; удалённые сообщения и голосовые разговоры не восстанавливаются. Стикеры и внешние изображения в карточках представлены метаданными, не копиями файлов.

При ошибке чтения, скачивания или отправки, а также превышении лимита загрузки Discord канал заявки не удаляется. Если отправка прошла, а удаление канала не удалось, повторное нажатие создаст свежий архив. В старом закрытом тикете нажмите прежнюю кнопку «Закрыть заявку» — бот покажет кнопку архива лично вам. Кнопки работают после перезапуска. Не выдавайте посторонним ролям доступ к каналу транскриптов.

Транскрипты хранятся только в Discord: временные файлы удаляются после операции. SQLite по-прежнему хранит настройки, состояние заявок и ID отправленного архива, но не переписку.

- `application.json` — название, описание и поля анкеты (до пяти). После изменения перезапустите бота; для обновления текста панели опубликуйте её заново и удалите старое сообщение.
- `tickets.sqlite3` — настройки сервера и состояние тикетов. Не удаляйте при перезапуске. Анкеты и переписка хранятся в Discord.
- `.env` — секретный токен и ID сервера. Файл и база исключены из Git.
- `bot.py` — первая версия бота. Новые функции можно добавлять постепенно.

Документация: https://docs.discord.com/developers/topics/oauth2 и https://discordpy.readthedocs.io/en/stable/interactions/api.html
